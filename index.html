100 Apps: Which Can Become Agent Toolkits Today?

Executive Summary & Objective: Comprehensive research and verification across 100 enterprise and consumer SaaS platforms to determine feasibility as agent-callable Composio toolkits. Evaluates authentication methods, self-serve developer access vs partner gating, public API surfaces, and official/community Model Context Protocol (MCP) servers. Verified through automated citation-checking, a 20-app stratified ground-truth sample (improving accuracy from 47% to 97%), and a 12-app retrospective holdout evaluation (100% verified).

The Patterns (Headline Insights)

  1. Most of the list is an immediate win (82% buildable): 64 of 100 apps hand a developer free or instant trial credentials with standard REST or GraphQL surfaces. Another 18 work with minor caveats (store-level app installs, tier-specific endpoints, or lightweight review before deployment).
  2. Tokens and Keys dominate single-tenant tools; OAuth2 dominates multi-tenant agents: 86 apps provide API keys, tokens, or bearer secrets; 74 offer OAuth2 authorization code or client credentials; 8 rely on HTTP Basic. Toolkits designed for end-user delegation require OAuth2, while server-to-server or private automation toolkits favor keys.
  3. Gating clusters in three distinct industry silos:
    • Advertising & Social: Google Ads, Meta Ads, and LinkedIn Ads mandate developer token reviews or business verification.
    • Fintech & Enterprise SaaS: Brex, Ramp, PitchBook, Otter AI, DealCloud, Gladly, Aircall, and Pylon require paying customer accounts or CSM onboarding.
    • Data & Intel Providers: Waterfall.io and Ahrefs lock their APIs behind sales calls or enterprise tiers.
  4. The primary bottleneck is administrative, not architectural: For 16 gated apps, public documentation is rich and APIs are standard REST/GraphQL. The only impediment is provisioning a live tenant sandbox for testing.
  5. MCP has achieved industry-standard velocity: 85 apps offer official vendor MCP servers (or first-party open-source implementations). 9 rely on community implementations (e.g., Discord, Telegram, SendGrid, Threads), and only 6 remain undocumented.

Self-Serve vs Gated Access by Category

Self-serve: Free instant signup or self-serve developer sandbox. Tiered: Instant sandbox/test mode; paid plan or verification required for live production. Gated: Mandates active customer subscription, enterprise tier, or sales approval.

The Agent: What It Does & Where a Human Was Needed

Stage 1
Evidence Collection Runs 3 targeted web searches per app (auth specs, pricing/gating, MCP ecosystem). 300 total search bundles saved in data/search/.
Stage 2
Keyword Baseline (Pass 1) Heuristic regex scanner across search snippets. Intentionally naive baseline to measure why rule-based scrapers fail (47% accuracy).
Stage 3
Structured AI Reviewer (Pass 2) Synthesizes condensed documentation snippets into strict typed JSON schemas with URL containment validation for every claim.
Stage 4
Deterministic Citation Check Fetches raw vendor documentation pages over HTTP (300 pages saved in data/pages/). Flags unsupported claims (25 claims flagged).
Stage 5
Stratified & Holdout Audit (Pass 3) Deep verification over a 20-app stratified sample (60 fields) and a 12-app holdout evaluation (33 checkable fields) to drive accuracy to 97%+.
Where a Human Was Required
  • Disambiguating Homonyms & Third-Party Repos: Products sharing names with unrelated software (e.g. Sherlock CLI username hunter, Paygent Connect NMI proxy, YouTube Transcript third-party wrappers vs official YouTube Data APIs).
  • Formulating the "Tiered" Classification: Recognizing that platforms like Meta Ads, Pinterest, Binance, and Ecwid allow free testing/sandboxing, but restrict live production deployment behind business review or paid plans.
  • Triaging Paywalled Vendor Portals: When enterprise platforms (e.g. PitchBook, DealCloud) restrict API references behind customer credentials, flagging them as gated rather than speculating.

Honest Audit of Errors & False Positives

  • Why naive regex failed (Pass 1): Scored only 28/60 (47%). Because terms like "partner", "pricing", and "approval" appear on virtually every enterprise footer, naive keyword matching falsely marked 91 of 100 apps as Gated. Contextual reasoning is indispensable.
  • Real inaccuracies caught in Pass 2 (2): WooCommerce REST API uses HMAC / OAuth 1.0a (or Basic over HTTPS), not OAuth2. Ecwid's API requires an active paid store tier rather than a free tier.
  • Taxonomy corrections (2): Meta Ads was initially marked Gated, but corrected to Tiered because sandbox development is free. Binance was adjusted to Tiered due to KYC requirements for live production keys.
  • Citation repointing: 6 MCP claims were repointed or downgraded (e.g., Shopify's internal doc states their MCP server is not publicly available yet; fanbasis only had third-party videos; WhatsApp cited an external news article).
  • Scoring edge cases: Salesforce (JWT bearer flow) and Jira (API tokens used over Basic HTTP) remain intentionally noted as subtle misses in strict scoring (58/60) to maintain rigorous integrity.

Runnable Proof & Pipeline Commands

The entire repository is built with standard Python 3 (zero third-party package dependencies). Run all verification loops and reproduce metrics in seconds:

# 1. Recompute and verify all accuracy scores (reproduces metrics.json):
python score_repro.py

# 2. Run automated claim-vs-source citation checks on fetched vendor docs:
python autocheck.py

# 3. Test mock live search and LLM review protocol:
python tests/test_live_protocol.py

# 4. Regenerate this report and results.json:
python gen_report.py
Honest Scope & Production Boundaries
  • Deterministic Offline Replay: collect.py and review.py feature offline replay modes (default), ensuring that reviewers can reproduce the entire dataset without needing paid API keys.
  • Live Execution Modes: Both collect.py --live (Brave Search API) and review.py --live (OpenAI-compatible LLM endpoint) are fully implemented and verified via local mock servers in tests/.
  • No Paid Accounts Purchased: Per assignment instructions, gated apps were documented using official vendor documentation and developer terms, which is the correct product finding.
