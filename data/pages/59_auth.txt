# Authentication

> Get access to the Waterfall API, send your API key in the x-api-key header, and manage keys for separate workflows.

Authenticate data and account API requests with your Waterfall API key in the `x-api-key` header. Contact the team (support@waterfall.io) for API access and pricing.

```http
x-api-key: YOUR_API_KEY

```

> [!NOTE]
> 
> The API host is `https://api.waterfall.io`. Data endpoints use `/v1/`; Account Reporter V2 uses `/v2/account`. Use the path shown on each reference page.

## Best practices

- Store keys in server-side environment variables. Keep them out of browser code and public repositories.
- Rotate keys periodically.
- Use dedicated sub-keys to manage access and usage for separate teams or workflows. Creating and managing sub-keys requires a master API key.

Missing keys return `401`. Invalid keys return `403`; this status can also indicate that a feature or permission is unavailable to the key. Inspect the error `code` using the Errors guide.

Follow the quickstart to make your first request, or use Agent Skills to build with an agent.
